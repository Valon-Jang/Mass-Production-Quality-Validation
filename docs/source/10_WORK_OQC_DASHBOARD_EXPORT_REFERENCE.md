## 1. 목적

사용자가 원본 OQC와 복잡한 메뉴를 찾아다니지 않고:

- 최신 이상
- 부품별 품질상태
- 검사항목 누적 Trend
- 출하수량·Coverage
- 업체평가·공급 안정성
- 정기검사 예정

을 필요한 깊이만큼 단계적으로 확인하도록 한다.

---

## 2. OQC Module 기본 Navigation

상단 메뉴:

- 모델 현황
- 이상 / Issue
- 업체평가
- 정기검사
- Export
- 관리기준 설정

프로그램 실행 시 신규 OQC가 없어도 바로 모델별 현황판을 보여준다.
신규 OQC 처리는 뒤에서 수행하고 확인이 필요한 변화만 상단에 표시한다.

---

## 3. 모델별 현황판

### 정렬 우선순위

- 미확인 이상
- 공급 안정성 Risk / 관찰
- 정기검사 지연
- 출하 전 Coverage 부족
- 정상 모델

### 모델카드 기본정보

- 모델명
- 최신 OQC 일자
- 미확인 / 진행 Issue 수
- 공급 안정성
- 판단 신뢰도
- 누적 부품 출하실적 또는 모델 출하실적
- 최근 이상 관련 Exposure
- 현재 생산상태

모델 자체 출하 Source가 없으면 부품수량을 모델 출하량으로 대체하지 않는다.

## 5. 모델 Dashboard

### 상단: 최신 OQC 변화요약

- 신규 Spec 이탈
- 기존 대비 악화
- 개선항목
- 데이터 신뢰성 의심
- 공차·기준 변경
- 검사주기·Coverage
- AI 핵심판단 3~5줄

각 요약문은 관련 검사항목 상세로 연결한다. AI 핵심판단의 각 문장도 별도 링크를 가져, 해당 판단을 만든 Trend·Sample·비교 LOT로 바로 이동한다.

### 중단: 부품별 상태

예:

- Top Tray: 이상 2
- Bottom Tray: 정상
- Out Box: 함수율 주의
- Pallet: 치수 Shift

### 하단: 부품별 검사항목 Card

예:

- 높이 / 최신 102.31 mm / 최근 5 Lot +0.08 / Cpk 1.42 / 관찰
- 함수율 / 7.8% / 최근평균 +21% / 주의
- 외관 / NG 2/100 / 신규 불량유형

## 19. 기간 비교

사용자가 직접 두 기간을 선택할 때만 실행한다.

예:

- 개선 전 4주 ↔ 개선 후 4주
- 4M 전 ↔ 후
- 1분기 ↔ 2분기
- 업체 A 최근 3개월 ↔ 업체 B 최근 3개월

비교:

- 평균
- 산포
- Cpk
- 이상발생
- 출하실적
- Coverage
- 주요 변화항목

AI가 변화의 의미를 요약한다.
차이가 큰 항목을 누르면 원인 LOT·Sample까지 내려간다.

## 20. 신규 Spec 검토

상시 계산하지 않고 사용자가 `신규 Spec 검토`를 실행할 때만 작동한다.

### 구분

- 도면 Spec 후보
- 사내 관리기준 후보

공정이 잘 만든다는 이유만으로 도면공차를 자동 Tightening하지 않는다.

### 입력근거

- 누적 공정분포
- 최근분포
- Cpk / Ppk
- 업체별 달성수준
- 기존 Spec Margin
- 실제 기능 / 조립 / 설비 요구조건
- 유사모델 Reference

기능한계 근거가 없는 항목은 도면 Spec 변경후보로 강하게 올리지 않는다.

### 시뮬레이션

후보 Spec을 과거 데이터에 가상적용하여:

- 과거 Fail률
- 최근 Fail률
- 업체별 Cpk
- 예상 향후 이탈확률
- 평균 Shift 시 Risk
- 병목업체

를 보여준다.

AI가 자동변경하지 않고 사용자가 승인한다.

### 부하

결과에는 DB Version과 후보조건을 저장한다.
같은 조건 재조회 시 Cache를 사용하고 신규 OQC가 추가되면 재분석 필요로 표시한다.

## 21. 검사항목 검색과 과거 Reference

특정 항목을 검색하면 활성·Archive 모델을 모두 찾는다.

예: `BCT`

- 모델별 Spec
- 관리기준
- 검사주기
- 측정방법
- 공정능력
- 정상 출하실적
- 과거 이상·개선이력

을 비교한다.

다른 모델 데이터를 하나의 통계로 합치지 않는다.

---

## 22. 신규 모델 Reference

프로그램이 첫 OQC의:

- 부품구성
- 검사항목
- Spec 구조
- 측정방법

을 비교해 유사모델 후보를 제안한다.

후보평가:

- 구조 유사도
- 재질
- 중량
- 사용조건
- 적재조건
- 양산 Lot·출하실적
- 품질 안정성
- 데이터 충분성

예:

- 모델 A: 90% 유사 / 50만 EA / 안정 → 우선 Reference
- 모델 B: 75% 유사 / 120만 EA / BCT 우수 → 보조
- 모델 C: 95% 유사 / 3 Lot → 데이터 부족

---

## 23. Reference 적용구분

과거 기준을:

- 그대로 적용 가능
- 조건 차이로 재검토 필요
- 제외 검토
- 신규 검증 필요

로 분류한다.

과거 Reference 상태:

- 검증 Reference
- 개선이력 포함 Reference
- 주의 Reference

숫자뿐 아니라 과거 품질이력을 함께 보여준다.

---

## 24. 신규 모델 초기 제안안

Reference 선택 후 프로그램이 초안을 만든다.

- 관리항목
- Spec / 관리기준 후보
- 검사주기
- 중요 CTQ
- 측정방법
- 재활용 가능 검증
- 신규 검증 필요항목

화면은:

- 그대로 적용
- 수정 필요
- 제외 검토

로 미리 분류한다.

사용자가 한 번에 초기기준을 확정한다.

---

## 25. 신규 모델 초기운영

설정 확정 후 첫 OQC부터 Ramp-up으로 시작한다.

- 유사모델 데이터는 Reference
- 신규 모델 자체 기준선은 실제 OQC로 생성
- 초기 열세항목은 강화관리 제안
- 정상 양산 Gate 통과 후 정식 업체평가 시작

유사모델 대비 열세는 바로 Fail이 아니라 `초기 공정능력 열세`로 표시한다.
