# WORK_OQC_ISSUE_SUPPLY_STABILITY

**Work Type:** 수행영역 Living Context  
**관리 대상:** OQC 알림 / 이상 Issue / 개선효과 / 생산단계 / 향후 공급 안정성  
**상태:** 요구사항 확정 / Rule Threshold 미설정  
**Core:** `02_OQC_WORK_CORE.md`

---

## 1. 목적

검출된 OQC 이상을 일회성 팝업으로 끝내지 않고 동일 Issue로 지속 추적하며, 실제 개선효과와 생산단계를 반영하여 향후 공급 안정성을 선제 판단한다.

---

## 2. OQC Module 알림

알림은 Scheduler가 아니라 OQC Module이 만든다.

알림 클릭 시:

- 해당 모델
- 최신 LOT Dashboard
- 관련 부품
- 이상항목

이 바로 열린다.

### 알림 발생

- 신규 이상
- 기존 이상 악화
- 정상화 후보
- Spec / 공차 변경
- 데이터 신뢰성 Risk
- 신규 등록 / Mapping 확인
- 정기검사 지연
- 출하 전 Coverage 부족

### 알림 억제

- 정상 OQC
- 이미 관리 중인 동일 이상이 같은 수준으로 지속
- 승인된 방법·기준 유지
- 정상 정기검사 수신

미확인 이상은 사용자가 확인할 때까지 모델카드에 남긴다.

---

## 3. Issue 상태

- `미확인`
- `확인 완료`
- `조치 중`
- `정상화 확인`
- `Close`

`확인 완료`는 사람이 봤다는 뜻이며 해결됐다는 뜻이 아니다.

---

## 4. 동일 Issue 연결

같은 모델·부품·업체·검사항목·Failure Pattern이면 다음 LOT에서 새 Issue를 만들지 않는다.

기존 Issue에 누적:

- 최초 발생 LOT
- 지속 LOT 수
- 최근 발생 LOT
- 변화 추세
- 악화 여부
- 조치시점
- 조치 후 데이터

정상화 후 장기간 지나 다시 발생하면 `재발`로 표시한다.

---

## 5. 정상화와 Close

다음 LOT 1회 정상으로 바로 Close하지 않는다.

예:

- 1 Lot 정상 → 관찰 중
- 2~3 Lot 연속 정상 → 정상화 후보

항목 중요도·생산단계·검사주기에 따라 연속 정상조건을 다르게 설정한다.

### 중요 Issue

다음은 사용자 확인 후 Close:

- Spec 이탈
- Master Spec 불일치
- 중요 CTQ
- 반복 재발
- 데이터 신뢰성 중대이슈

### 경미 Issue

일시적 산포·경미 Trend는 조건 충족 시 자동 Close 가능하다.
자동 Close 이력은 보존한다.

BCT처럼 주기검사는 Lot 수가 아니라 검사 2~3회 연속정상으로 본다.

---

## 6. Issue 우선순위

Issue 우선순위는 다음을 함께 반영한다.

- Spec 이탈 및 중요 CTQ 여부
- Spec Margin과 변화크기
- 지속 Lot 수 / 재발
- 데이터 신뢰성 중대도
- 기출하 Exposure와 추가 출하예정
- 생산단계

같은 이상이라도 출하 전 0 EA와 이미 대량 출하된 경우를 구분한다.

---

## 7. Issue 기록정보

사용자가 간단히 입력 가능:

- 원인
- 업체 조치
- 조치일
- 확인 필요사항
- 완료조건

AI가 제안할 수 있으나 자동 확정하지 않는다.

---

## 8. 원인 후보

실제 이상 Issue에만 AI 분석을 실행한다.

입력:

- 이상항목 통계 Feature
- 동반변화
- 생산일·작업조
- 금형·Cavity
- 4M·Spec·방법 변경
- 과거 유사 Issue

출력:

- 가능성 높은 원인 후보
- 후보별 근거
- 추가 확보정보
- 업체 확인사항

원인을 사실로 단정하지 않는다.

업체 메일은 자동 발송하지 않고 요청안까지만 준비한다. 이전 Issue에 업체조치가 기록되어 있으면 다음 OQC에서 해당 항목의 평균·산포·Cpk·재발 여부를 자동 비교해 `조치 효과 확인 / 미개선 / 재발`로 갱신한다.

---

## 9. 개선효과 판정

업체의 `개선 완료` 문구로 인정하지 않는다.

실제 OQC에서:

- 개선 전·후 평균
- 산포
- Cpk
- Spec 근접률
- 동일 이상 재발
- 정상 Lot 수
- 개선 후 정상 출하수량

을 확인한다.

상태 예:

- 개선효과 미확인
- 초기 개선 확인
- 개선 정착 관찰
- 개선 정착
- 재발

개선이 한 번 확인됐다고 영구 가점으로 남기지 않는다.
충분한 정상 Lot·출하실적이 쌓이면 현재 안정 품질수준으로 흡수한다.

---

## 10. 개선효과의 활용

개선 전후 결과는 업체평가 점수 가점보다 **향후 공급 안정성 예측**에 우선 활용한다.

원칙:

- 문제 없이 안정한 업체가 문제를 많이 만들고 잘 고친 업체보다 우선
- 개선 성공은 인정하지만 과거 발생이력은 보존
- 개선 후 Cpk 회복·산포 감소·재발 없음·출하실적이 공급 Risk 저감 근거

---

## 11. 향후 공급 안정성

기본 평가단위:

**모델 → 부품 → 업체**

최종 표시는:

- `안정`
- `관찰`
- `Risk`

그리고 별도 `판단 신뢰도: 높음 / 보통 / 낮음`을 표시한다.

---

## 12. 공급 안정성 분리축

### 제품 품질 안정성

- Cpk
- 평균·산포 Trend
- Spec 이탈
- 중요 CTQ
- 반복 이상
- 개선 정착
- 정상 출하실적

### OQC 운영 안정성

- OQC 제출기준 준수
- 정기검사 준수
- Coverage
- 데이터 신뢰성
- 품질근거 미완성 출하 반복

### 종합 공급 안정성

두 축을 종합하되 원인을 구분해서 보여준다.

예:

- 제품 품질 안정성: 안정
- OQC 운영 안정성: 관찰
- 종합: 관찰

---

## 13. 공급 안정성 입력요소

- 최근 공정능력
- 장기 공정능력
- 산포·평균 방향성
- 중요 CTQ Hard Gate
- 반복 이상·재발
- 개선 후 정착여부
- 누적 정상 출하실적
- 정기검사 최신성
- OQC Coverage
- 데이터 신뢰성
- 생산단계
- 최신 데이터 충분성

---

## 14. 선제 경고

현재 Cpk가 양호해도 최근 지속하락하면 선제 경고한다.

예:

`1.95 → 1.88 → 1.81 → 1.76 → 1.72`

결과:

- 현재 Spec 문제 없음
- 안정등급 유지 가능
- `안정 → 관찰 전환 가능성` 표시

어떤 항목이 Risk를 끌어올리는지 기여도 또는 우선순위를 보여준다.

예:

- 높이 Cpk 하락
- 함수율 상승
- BCT 최근 하락
- Coverage 부족

정확한 % 기여도는 Rule이 설명 가능한 경우에만 사용하고, 아니면 순위로 표시한다.

---

## 15. 선행 확인항목

Risk 상승 시 자동으로 다음 확인을 제안한다.

- 높이 Cpk 하락 → 금형·공정조건 변경여부
- 함수율 상승 → 원재료·보관조건
- BCT 하락 → 원지·함수율·생산조건
- 데이터 신뢰성 → 원본 측정기록
- 특정 Cavity → 금형 위치·조건

현재 DB에 없는 정보를 확인할 대상으로 구분한다.

---

## 16. 중요 CTQ Hard Gate

- 중요 CTQ Spec 이탈 → 최소 관찰
- 반복 이탈 / 급격한 Cpk 저하 → Risk
- 중요 정기검사 최신값 없음 → 안정 확정 금지
- 평균점수로 상쇄하지 않음

CTQ와 Gate는 모델·부품별 설정한다.

---

## 17. 생산단계

### 단계

- 초기 생산 / Ramp-up
- 안정화 확인 중
- 정상 양산
- 4M·금형수정 후 재안정화
- 장기중단 후 재공급 검증

### 자동판단 Source

- 신규 업체 첫 공급
- 신규 모델 첫 생산
- 4M / 금형수정 Event
- 공급중단·재개
- 안정화 Gate 통과

프로그램 판단은 사용자가 수정 가능하다.

---

## 18. 초기 생산 / Ramp-up

초기 데이터는 정상 양산 기준선에 바로 섞지 않는다.

확인:

- Cpk 목표 접근
- 평균 Shift 감소
- 산포 안정
- Spec 이탈 반복여부
- 중요 CTQ 정상화
- BCT 등 정기검사 확보

화면은 항목별 안정화 상태와 Gate 미통과 사유를 보여준다.

예:

- 높이: 안정화 완료
- 평탄도: 산포 감소 중
- BCT: 검사횟수 부족
- 외관: 동일 NG 반복

---

## 19. 정상 양산 전환 Gate

모델·부품별 다르게 설정한다.

예:

- 일반 치수 최근 3 Lot 안정
- 중요 CTQ 최근 5 Lot + Cpk 기준
- BCT 2회 연속 정상
- 외관 동일 NG 재발 없음
- 미해결 신뢰성 Issue 없음

Lot 수 경과만으로 자동 전환하지 않는다.

---

## 20. 초기 강화관리

유사 모델 Reference 또는 초기 데이터 대비 특정 항목이 열세면 프로그램은 강화관리를 **제안**한다.

예:

- Sample 수 임시 확대
- 중요 CTQ 임시 지정
- 3 Lot 연속 확인
- 정기검사 조기 실시

사용자 승인 후 적용한다.

### 임시와 정규 분리

- 임시 강화기간
- 적용사유
- 종료조건
- 결과

을 관리한다.

안정화되면 정규 기준 복귀 후보를 제안한다.
계속 필요하면 사용자가 정규 관리기준으로 승격한다.

---

## 21. 4M·금형수정 후 재안정화

Trend에 변경시점을 표시한다.

- 변경 전 기준선
- 변경 후 데이터 축적
- 변경 전후 평균·산포·Cpk

변경 직후 새 기준선을 즉시 확정하지 않는다.
3~5 Lot 또는 항목별 Gate로 안정화 확인 후 새 공정 기준선을 만든다.

Master Spec은 자동변경하지 않는다.

---

## 22. 공급중단과 재공급

공급중단 기간에는:

- 정기검사 지연 감점 없음
- OQC 없음 감점 없음

장기 중단 후 재개하면:

- 재공급 검증 상태
- 초기 중요 CTQ 연속확인
- 정기검사 우선확인
- 충분한 정상데이터 후 정상 양산 복귀

과거 기준선은 Reference로 남기고 재공급 후 새 공정 기준선을 생성한다.

---

## 23. 공급 안정성 판단 신뢰도

다음으로 판단한다.

- 기간
- Lot 수
- 실제 출하수량
- 중요항목 최신성
- Coverage
- 생산단계

예:

- 12개월 / 85 Lot / 52만 EA / 최신 정기검사 확보 → 높음
- 1개월 / 3 Lot / BCT 미확보 → 낮음

데이터가 부족하면 `안정`을 강하게 단정하지 않는다.

---

## 24. 증분 갱신

다음 Event가 있을 때만 해당 모델·부품·업체 안정성을 갱신한다.

- 신규 OQC
- 중요 CTQ 갱신
- 정기검사 Window 경과
- 4M·Spec·방법 변경
- 개선 후 정상데이터 추가
- 공급재개
- Coverage 변화
- 데이터 신뢰성 상태변경

전체 DB를 매번 재계산하지 않는다.

---

## 25. 현재 판단

### 확정

- 동일 이상은 하나의 Issue로 추적한다.
- 알림 확인과 Close를 분리한다.
- 개선효과는 실제 데이터로 판단한다.
- 공급 안정성은 제품 품질과 OQC 운영을 분리한다.
- 생산단계를 반영한다.

### 미확정

- 정상화 Lot 수 기본값
- 생산중단 장기 기준
- 공급 안정성 Rule Threshold
- 중요 CTQ별 Gate

---

## 26. Gate

### Issue Gate

- 동일 Issue 연결
- 악화 / 정상화 / 재발 판정
- Close 이력

### Stability Gate

- 제품 품질 / OQC 운영 / 종합 분리
- 생산단계 반영
- 판단 신뢰도
- 최근 악화 선제경고

### Ramp-up Gate

- 항목별 미완료 사유
- 임시 강화관리 승인·종료
- 정상 양산 전환조건

---

## 27. Resume Point

품질분석 Engine 이후:

1. 이상유형별 Issue Key 정의
2. 동일 Issue 지속·악화·정상화 Test
3. 제품 품질 안정성과 OQC 운영 안정성 Rule 분리
4. 초기 생산 Dummy Data로 정상 양산 Gate 검증
5. 4M 전후 새 기준선 전환 Test
