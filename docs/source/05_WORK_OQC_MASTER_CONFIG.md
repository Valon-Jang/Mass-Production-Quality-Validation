**Work Type:** 수행영역 Living Context  
**관리 대상:** Master Spec / 업체 OQC 제출기준 / 관리항목 / 검사주기 / 측정방법 / 사용자 정의 항목  
**상태:** 요구사항 확정 / 실제 기준자료 미등록  
**Core:** `02_OQC_WORK_CORE.md`

---

## 1. 목적

업체 OQC의 양식과 기재값에 끌려가지 않고, 프로그램이 사용할 **당사 기준·관리 Scope·검사주기·측정방법·업체 제출요구**를 Version과 적용일 기준으로 통제한다.

---

## 2. Master Spec

검사항목별 최소 관리정보:

- 모델
- 부품
- 검사항목
- Target
- LSL / USL
- 단위
- Revision
- 적용 시작일
- 변경 전 / 후
- 변경 사유
- 근거 문서
- 승인자 또는 승인 상태

### 원칙

- OQC 기재 Spec을 자동으로 Master로 인정하지 않는다.
- 업체가 공차를 완화해도 사용자 승인 전에는 기존 Master를 유지한다.
- 과거 데이터는 당시 적용 Revision 기준 판정을 보존한다.
- 현재 Master 기준 재평가는 별도 옵션으로 수행한다.
- Master Revision 변경은 과거값을 덮어쓰지 않는다.

### 자동 비교

신규 OQC 입력 시:

1. 기존 OQC의 최근 Spec
2. 적용일 기준 Master Spec
3. 최신 OQC 기재 Spec

을 대조한다.

변경항목은 `이전 → 현재`, 적용일, 승인상태를 정확히 보여준다.

---

## 3. Spec Revision 영향분석

Master가 변경되면 필요 시 다음을 On-demand 계산한다.

- 과거에는 PASS였으나 신규 기준이면 FAIL인 데이터
- 변경 전·후 예상 Fail Lot / Sample
- 업체별 Cpk·Margin 변화
- 공정 여유 부족 여부

Spec Revision이 바뀌었다는 이유로 모든 과거 통계를 즉시 재계산하지 않는다.

---

## 4. 업체 OQC 제출 필수항목

기본 필수항목:

- 모델
- 부품명 / 품번
- 업체
- LOT
- 검사일
- Spec Revision
- 금번 출하수량
- 업체 기준 누적 출하수량

생산일, 생산공장, Line, 금형, Cavity, 작업조 등은 모델·부품별 필요에 따라 추가 필수화할 수 있다.

필수항목 목록은 프로그램 내 `업체 OQC 제출 기준` 화면에서 조회·수정한다.

누락 시:

- 어느 필수항목이 빠졌는지 직접 표시
- 품질데이터 중 정상부분은 적재 가능
- 출하·비교에 필요한 영역만 보류

---

## 5. 업체 OQC 제출 기준 Version

제출기준에는 다음을 포함할 수 있다.

- 필수 식별정보
- 필수 출하정보
- 관리 검사항목
- 항목별 Spec·단위
- 검사주기
- Sample 수
- Cavity별 Sample 요구
- 중요 CTQ
- 승인 측정방법
- 이번 제출 시 포함해야 하는 정기검사

관리정보:

- Version / Revision
- 적용 시작일
- 변경자
- 변경 전 / 후

신규 OQC는 검사일·적용일을 기준으로 당시 유효 제출기준과 비교한다.

프로그램은 현재 제출기준을 업체 전달용 Excel 또는 표준 체크리스트로 Export할 수 있어야 한다.

## 6. 모델별 관리항목 Scope

OQC에 존재하는 모든 항목을 자동 분석하지 않는다.

각 모델·부품·항목에서 다음을 설정한다.

- `관리`
- `분석 제외`
- `신규 관리항목 후보`
- 중요 CTQ
- Item Type
- 관리기준
- 검사주기
- Sample 요구
- 측정방법
- Point 정의

### 신규 검사항목

- 데이터는 보존
- 즉시 공식 Trend에 섞지 않음
- 사용자에게 `관리 / 분석 제외 / 기존항목 Mapping` 선택 제공
- 한 번 결정하면 이후 자동 적용

---

## 7. Item Type

기본 유형:

- 연속형 치수
- 일방향 상한관리
- 일방향 하한관리
- 물성 / 강도
- 외관 OK/NG
- 외관 불량유형·발생수
- 다중 Point
- 좌표 X/Y
- 사용자 정의 계산항목

Item Type에 따라 기본 통계·그래프·이상 Rule을 다르게 적용한다.

---

## 8. 검사주기

항목별 주기 예:

- 매 LOT
- 주 1회
- 월 1회
- 4~5주 1회
- 사용자 지정 Window
- 초기 3 Lot 연속
- 정기검사 2회 연속

### BCT 예

BCT를 4~5주 1회로 설정하면 매 LOT 누락으로 잡지 않는다.

- 4주 진입: 검사 예정
- 5주까지: 허용 Window
- 5주 초과: 주기 초과

### 공급상태 고려

- 실제 납품 중인 기간만 주기를 계산한다.
- 공급중단 중에는 지연 감점하지 않는다.
- 재공급 시 재검증 규칙을 적용한다.

### 다음 검사 예정

모델·부품 Dashboard 및 전체 정기검사 화면에:

- 마지막 검사일
- 다음 검사 Window
- 예정 / 정상 / 지연

을 표시한다.

## 9. Sample 및 Point 기준

항목별로 설정 가능:

- 기본 Sample 수
- Cavity별 Sample 수
- Point 목록
- Point 명칭과 정의
- 생산일·작업조 Sub-group 기준

최신 OQC에서:

- Sample 수 부족
- 특정 Cavity만 Sample 부족
- 기존 Point 누락
- Point 추가·순서변경

을 구분한다.

전체 Sample 수가 맞더라도 특정 Cavity가 미검사면 별도로 표시한다.

## 10. 측정방법

관리대상은 장비 ID·검교정이 아니라 **측정방법**이다.

예:

- 자
- 줄자
- 버니어캘리퍼스
- 하이트게이지
- 3차원 측정
- 전자 조도계
- 육안
- BCT 시험

### 기준관리

검사항목별로:

- 현재 승인방법
- 승인 가능한 대체방법
- 미승인 신규방법
- 적용 시작일

을 관리한다.

### 신규방법 처리

1. 기존 방법 → 신규 방법 변경 표시
2. AI가 공차·측정목적·형상 기준 적절성 검토
3. 사용자가 승인
4. 이후 같은 모델·부품·항목에서는 자동 인정

부적절하면 `측정방법 재검토 / 재측정 필요`로 표시한다.

합의된 방법 변경은 업체평가 감점이나 데이터 신뢰성 Penalty에 자동 연결하지 않는다.

### 반복기재 원칙

업체가 OQC마다 승인된 측정방법 문구를 반복하지 않더라도, 해당 업체·모델·부품·항목에 확정된 방법이 있고 변경징후가 없으면 매번 누락으로 경고하지 않는다. 새로운 방법표기나 데이터특성 변화가 있을 때만 변경여부를 확인한다.

### 재측정

부적절한 방법으로 측정된 뒤 적절한 방법의 재측정값이 들어오면:

- 최초값은 `부적절한 측정방법 데이터`로 이력 보존
- 재측정값만 공식 통계에 사용
- 최초값 때문에 생성된 이상은 재측정 반영 이력과 연결

### 비교조건

방법 변경 전후 평균·산포 변화가 없으면 장기 Trend를 유지하며 변경점만 표시한다.
변화가 크면 전후 통계를 구분하고 최신은 변경 후 데이터와 우선 비교한다.

---

## 11. 사용자 정의 항목

기존 측정항목을 조합해 신규 관리항목을 만든다.

예:

- `Clearance = 내측치수 - 제품치수`
- `좌우편차 = ABS(좌측 - 우측)`
- `적층여유 = Box 내부높이 - Tray/제품 적층높이`

지원 기본연산:

- 사칙연산
- 절대값
- 차이
- 합계
- 필요 시 승인된 단순 함수

### 원칙

- 일반 검사항목과 동일하게 Trend·Spec·Cpk·이상분석 가능
- 입력값 하나라도 없으면 계산하지 않음
- 이전값·평균값으로 임의 보정하지 않음
- 결측 원본항목을 정확히 표시

### Revision

계산식 변경 시:

- 이전식 / 신규식
- 적용 시작일
- 변경사유

을 보존한다.
과거 전체를 신규식으로 재계산하는 기능은 On-demand다.

---

## 12. 중요 CTQ와 관리기준

검사항목별 설정:

- 중요도 / 가중치
- Cpk 관리기준
- Spec 근접경고 수준
- NG 허용기준
- 공급 안정성 Hard Gate
- OQC Coverage 요구수준

중요 CTQ는 평균점수로 묻히지 않는다.

예:

- 중요 CTQ Spec 이탈 1건 → 최소 `관찰`
- 중요 CTQ 반복 이탈 또는 급격한 Cpk 저하 → `Risk`
- 최신 정기검사 미확보 → `안정` 확정 금지

---

## 13. 설정 상속과 Override

권장 구조:

1. 전 프로젝트 공통설정
2. 부품 Type 공통설정
3. 모델 설정
4. 모델·부품 Override
5. 업체별 승인 예외

예:

- 공통 필수항목
- Box 공통 함수율/BCT
- 특정 모델 Out Box BCT 4~5주
- 특정 업체만 승인된 별도 측정방법

모델이 늘어나도 설정을 전부 다시 만들지 않는다.

---

## 14. 설정 복사와 신규 모델

- 기존 유사 모델의 설정만 복사 가능
- OQC 데이터·업체평가 이력은 복사하지 않음
- 프로그램이 구조·항목 유사도 후보를 제안
- 사용자가 Reference 모델 선택
- 실제 신규 OQC와 비교해 다른 부분만 확인

확인항목:

- 신규·누락 부품
- Spec 차이
- 검사주기 차이
- 측정방법 차이
- 불필요하게 복사된 항목
- 신규 구조 관련 항목

초기 설정 확정 Gate 전에는 업체평가·공급 안정성을 확정하지 않는다.

---

## 15. 설정 변경과 과거 재평가

설정 변경 시:

- 기본은 변경시점부터 적용
- 과거 데이터와 당시 판단은 유지
- 과거까지 신규 기준으로 보고 싶을 때만 `과거 데이터 재평가`
- 전체 DB를 상시 재계산하지 않음

관리자 권한과 Audit Log를 적용한다.

---

## 16. 현재 판단

### 확정

- Master와 업체 OQC Spec은 분리한다.
- 필수항목과 관리 Scope는 프로그램에서 수정 가능하다.
- 검사주기는 Window와 공급상태를 고려한다.
- 측정방법만 관리하고 장비 ID·검교정은 제외한다.
- 사용자 정의 항목을 Revision과 함께 관리한다.

### 미확정

- 실제 모델별 Master Spec
- 기본 Cpk·Coverage·CTQ Threshold
- 업체 제출기준 첫 Version

Threshold는 실제 데이터와 사용자 기준을 받아 설정한다. 임의 확정하지 않는다.

---

## 17. Gate

### Master Gate

- 모델·부품·항목별 적용 Spec Revision 등록
- OQC 기재 Spec과 대조 가능
- 사용자 승인 전 자동변경 금지

### Submission Standard Gate

- 기본 필수항목 등록
- 검사항목·주기·Sample·방법 Export 가능
- 유효 Version과 신규 OQC 자동 대조

### Management Scope Gate

- 관리/제외/CTQ/주기/방법 설정
- 신규항목 처리
- 사용자 정의 항목 결측·Revision 처리

---

## 18. Resume Point

대표 OQC 확보 후:

1. 기본 필수항목 존재여부 확인
2. 해당 모델·부품의 Master Spec 초안 등록
3. 관리대상 / 제외대상 분류
4. 검사주기와 Sample 구조 등록
5. 측정방법 Mapping
6. 업체 제출기준 Version 1 생성
