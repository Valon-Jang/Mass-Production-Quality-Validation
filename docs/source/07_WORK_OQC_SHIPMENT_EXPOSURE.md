# WORK_OQC_SHIPMENT_EXPOSURE

**Work Type:** 수행영역 Living Context  
**관리 대상:** 출하수량 / 누적출하 검증 / 품질 Exposure / OQC Coverage  
**상태:** 요구사항 확정 / 실제 출하 Source 미연결  
**Core:** `02_OQC_WORK_CORE.md`

---

## 1. 목적

OQC 결과를 검사 Sample에만 가두지 않고 실제 출하수량과 연결하여:

- 업체·당사 누적수량 불일치
- 이상 Lot의 기출하·미출하·예정수량
- 출하물량의 OQC 근거 Coverage
- 출하 전 품질근거 미완성 Risk

를 판단한다.

품질검사 데이터와 출하 Exposure를 구분하며, OQC NG율을 전체 출하불량률로 임의 확대해석하지 않는다.

---

## 2. 업체 OQC 필수 출하정보

- 금번 출하수량
- 업체 기준 누적 출하수량

프로그램은 매 OQC에서 다음을 대조한다.

`직전 업체 누적 + 금번 출하 = 이번 업체 누적`

그리고:

`업체 기재 누적 ↔ 프로그램 DB 누적`

을 비교한다.

---

## 3. 누적 출하 기준키

기본 누적단위:

**모델 + 부품 + 업체**

Spec Revision이 바뀌어도 전체 누적은 리셋하지 않는다.

필요 시 구간별로:

- Rev.A 적용기간
- Rev.B 적용이후
- 4M 전후
- 특정 개선 전후

출하수량을 잘라서 본다.

---

## 4. 누적 불일치 검증

### 4.1 산술 불일치

- 직전 누적
- 금번 출하
- 이번 누적

이 맞지 않으면 업체 OQC 자체 산술오류로 표시한다.

### 4.2 프로그램 DB 불일치

예:

- 업체 누적 528,000 EA
- 프로그램 누적 516,000 EA
- 차이 12,000 EA

프로그램은 임의로 12,000 EA를 채우지 않는다.

### 4.3 최초 불일치 시점

- 마지막 일치시점
- 최초 차이 발생 OQC
- 이후 차이 증감
- 해당 구간 금번출하 합계

를 자동으로 찾아준다.

### 4.4 누적수량 역전

직전보다 이번 누적이 줄면 신규값으로 덮어쓰지 않는다.

가능성:

- 업체 기재오류
- 누적기준 변경
- 과거 데이터 정정

확인 전 공식 누적은 기존값을 유지한다.

### 4.5 정정 이력

업체 정정 시:

- 기존값은 오입력 이력으로 보존
- 승인된 정정값을 공식 누적으로 사용
- 관련 기간 누락·중복을 다시 검증

---

## 5. 여러 업체와 부품 누적

같은 부품을 A/B업체가 공급하면:

- 업체 A 누적
- 업체 B 누적
- 해당 부품 전체 누적 = 업체별 합계

을 본다.

단, 모델 전체 출하수량은 부품별 수량 합계로 계산하지 않는다.

예:

- Top Tray 700,000 EA
- Bottom Tray 700,000 EA

를 모델 1,400,000 EA로 계산하지 않는다.

모델 출하수량은 별도 모델 출하 Source가 있을 때만 표시한다.

---

## 6. 계획수량·실제출하·잔량

구분:

- 계획수량
- 실제 출하수량
- 미출하 잔량
- 출하 예정수량

Exposure는 실제 출하수량 기준이다.
계획수량은 향후 출하·차단 가능물량 판단에 사용한다.

---

## 7. 분할출하와 다대다 연결

### 한 LOT의 여러 출하

- 8/10 5,000 EA
- 8/15 3,000 EA
- 8/20 4,000 EA

→ LOT 누적 Exposure 12,000 EA

### 한 출하의 여러 생산 LOT

- LOT A + LOT B → 출하 20,000 EA

OQC LOT ↔ 출하건 관계를 1:1로 가정하지 않고 다대다 연결을 허용한다.

매칭정보가 없으면 임의 배분하지 않는다.

---

## 8. 출하 데이터 후입력

OQC가 먼저 들어오고 출하데이터가 나중에 들어와도 같은 모델·부품·LOT에 자동 연결한다.

- 품질분석은 출하정보 없이도 완료
- 출하영역은 `미확보`
- 후속 출하데이터가 들어오면 Exposure와 Issue를 갱신

LOT 표기가 다르면 연결후보를 제시한다.
애매하면 `미매칭 출하데이터`로 보류하고 사용자가 한 번 확정한 패턴은 재사용한다.

---

## 9. 이상 Issue의 영향수량

이상 발생 시 최소 표시:

- 해당 총 LOT 수량
- 이미 출하된 수량
- 미출하 잔량
- 출하 예정수량
- 영향 가능수량

프로그램이 출하를 자동 Hold하지 않는다.

### 범위 축소

- 생산일별 수량이 있으면 해당 Sub-group
- Cavity별 생산수량이 있으면 해당 Cavity

로 영향범위를 좁힌다.

정보가 없으면 Cavity 수로 균등분할하지 않고 LOT 전체를 잠재 Exposure로 표시한다.

---

## 10. OQC 검사율과 출하 Exposure 분리

예:

- OQC 50 EA 검사 / NG 1 EA
- LOT 출하 12,000 EA

표시:

- OQC NG율 2%
- 영향 가능 출하수량 12,000 EA

금지:

`12,000 EA의 2%가 불량`이라고 임의 추정.

---

## 11. 누적 정상 출하실적

현재 범위에서 표시 가능한 것은 **OQC 정상 출하실적**이다.

- 출하 당시 OQC 기준 이상 없음
- OQC 근거 확보
- 해당 Issue와 연결된 품질 Risk 없음

고객 Claim 데이터가 연결되지 않았으므로 `시장/고객 무이슈 실적`으로 부르지 않는다.

조회단위:

- 모델
- 부품
- 업체
- 검사항목 관련 정상실적
- 개선 후 정상 출하실적

---

## 12. OQC Coverage

정의:

`OQC 확인 완료 출하수량 / 실제 출하수량`

예:

- 출하 240,000 EA
- OQC 확인 236,000 EA
- Coverage 98.3%

### 미Coverage 원인

- OQC 미수신
- Mapping 보류
- LOT-출하 연결 실패
- 일부 부품 OQC 누락
- 수정본 확인 대기
- 중요 CTQ 보류

Coverage는 제품품질 Fail과 분리하고 `품질근거 확보 수준`으로 관리한다.

---

## 13. Coverage 기준

모델·부품별 설정 가능:

- 중요부품 100%
- 일반부품 별도 허용기준
- 초기 생산 / 재안정화 100% 우선
- 정상 양산 기준

Coverage 미달은:

- 제품 품질점수가 아니라
- OQC 관리 준수도
- 품질근거 신뢰도
- 공급 안정성 판단 신뢰도

에 반영한다.

---

## 14. 출하 전 선행경고

출하 예정이 있는데 Coverage가 기준미달이면 `출하 전 품질근거 미완성`으로 표시한다.

판단 시:

- 실제 출하 예정일
- OQC 제출 예정시점
- 중요 CTQ 상태
- 정기검사 Window

를 함께 본다.

예:

- 출하 3일 전, OQC 내일 예정 → 정상대기
- 출하 당일, OQC 미수신 → 확인필요

자동 Hold는 하지 않는다.

---

## 15. 품질근거 미완성 상태 출하

Coverage 미완성인데 출하가 진행되면 당시 상태를 이력으로 남긴다.

- 출하시점 Coverage
- 미확인 LOT / 부품 / 항목
- 실제 출하수량
- 보완 완료일

나중에 OQC가 들어와도 당시 미완성 상태 자체는 지우지 않는다.

반복원인:

- 업체 OQC 제출 지연
- 내부 Mapping 보류
- 출하정보 연결지연
- 정기검사 누락
- 수정본 확인지연

을 구분한다.

제품 품질안정성과 OQC 운영안정성을 분리하여 공급 안정성에 반영한다.

---

## 16. 출하 Trend

기본 조회:

- LOT별 출하량
- 월별 출하량
- 업체별 출하량
- 부품별 출하량
- 이상 발생기간 출하량
- 개선 후 정상 출하량

모델 자체 출하 Source가 없으면 부품수량으로 추정하지 않는다.

---

## 17. 현재 판단

### 확정

- 금번·누적 출하수량은 업체 OQC 필수정보다.
- 업체 누적과 프로그램 누적을 대조한다.
- 모델 출하와 부품 출하를 분리한다.
- OQC NG율과 출하 Exposure를 혼합하지 않는다.
- Coverage는 품질 Fail이 아니라 근거 확보수준이다.

### 미확정

- 실제 출하 Source와 Queue 연계
- LOT-출하 매칭 Key
- 모델·부품별 Coverage Threshold

---

## 18. Gate

### Quantity Gate

- 금번 + 직전 누적 = 현재 누적 검증
- 업체 누적과 DB 누적 일치
- 최초 불일치 시점 탐색
- 정정이력 보존

### Exposure Gate

- 실제/예정/잔량 구분
- 이상 Issue의 영향수량 계산
- 정보 부족 시 임의배분 금지

### Coverage Gate

- 출하와 OQC 다대다 연결
- Coverage와 누락원인 표시
- 출하 전 경고 및 미완성 출하 이력

---

## 19. Resume Point

대표 OQC에 금번·누적수량이 포함되면:

1. 업체 누적 산술검증
2. 동일 업체 3건 이상 누적 Test
3. 의도적 누락·중복 Test Data로 최초 불일치 시점 검증
4. OQC와 출하 데이터의 후입력 연결 Test
5. Coverage 계산과 누락원인 표시
